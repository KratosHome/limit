# Встановщики Limit

У цій папці після збірки з’являються два файли, які можна надіслати людям:

- `Limit-<версія>-win-x64.exe` — Windows x64.
- `Limit-<версія>-mac-universal.dmg` — macOS, Intel та Apple Silicon.

Збірка не потребує платних сертифікатів. Windows-встановщик не підписаний;
Mac-застосунок має локальний ad-hoc підпис і не нотаризований Apple.

## Як встановити

**Windows:** відкрийте `.exe` і пройдіть встановлення. Система може показати
попередження про невідомого видавця; політики деяких комп’ютерів можуть
забороняти запуск непідписаних програм.

**Mac:** відкрийте `.dmg`, перетягніть Limit у Applications і запустіть звідти.
Якщо macOS не дозволяє запуск невідомого розробника, після спроби відкриття
скористайтесь System Settings → Privacy & Security → Open Anyway для Limit,
якщо довіряєте джерелу файлу. Не потрібно вимикати захист для всього Mac.

## Оновлення

Після першого push коду з workflow у `main` GitHub Actions збирає й публікує
нову версію. Кожний наступний push у `main` створює наступний реліз лише після
успішних перевірок та збірок обох ОС.

Push не змінює вже встановлений застосунок одразу. Спочатку дочекайтесь
успішного запуску [Release у GitHub Actions](https://github.com/KratosHome/limit/actions/workflows/release.yml)
і появи нової версії у GitHub Releases. Якщо перевірка або збірка хоча б однієї
ОС завершилася помилкою, спільний реліз не публікується. Помилка
`No published versions on GitHub` у `logs/updates.log` означає, що Limit ще
не знайшов жодного опублікованого релізу. Після його появи виберіть перевірку
оновлень у меню Limit біля годинника.

- **Windows:** Limit перевіряє оновлення при запуску та кожні чотири години,
  завантажує їх у фоні й встановлює під час виходу через меню tray. Пункт
  «Перезапустити й оновити» дозволяє встановити завантажене одразу.
- **Mac:** Limit перевіряє нові версії та пропонує завантажити DMG. Потрібно
  завершити Limit через меню й замінити застосунок у Applications вручну.
  Ця збірка не намагається встановлювати оновлення через нативний updater.

Статистика й налаштування зберігаються окремо від встановленого застосунку.
Нові файли також доступні на [GitHub Releases](https://github.com/KratosHome/limit/releases).

## Як зібрати знову

З кореня проєкту:

```bash
npm ci
npm run installers:win # на Windows
npm run installers:mac # на macOS
```

Mac-збірка потребує macOS і Xcode Command Line Tools. Windows-збірку після
чистого `npm ci` запускайте на Windows: залежність `get-windows` встановлює
нативний модуль лише для поточної ОС. Кросзбірка на Mac можлива після окремої
підготовки Windows-модуля, як у середовищі, де створено поточний встановщик.
GitHub Actions використовує окремі Windows і macOS runners.
Команди копіюють відповідний встановщик у цю папку; проміжні файли й метадані
оновлень зберігаються у `release/publish/`.

Самі `.exe`/`.dmg` виключені з Git через великий розмір. Ця інструкція та код
збірки входять у репозиторій, а для завантаження людьми файли публікує GitHub
Releases. Службові `.zip`, `.yml` і `.blockmap` у релізі потрібно залишати.
