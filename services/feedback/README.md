# Limit feedback relay

Окремий серверний сервіс приймає відгук із головного процесу Electron і надсилає
його в один Telegram-чат. Токен бота та адресат зберігаються лише на сервері.
Застосунок передає тільки текст, необов'язковий контакт і розділ `health` або
`settings`. Дані трекінгу, здоров'я та бази SQLite автоматично не додаються.

## Локальний запуск

Потрібен Node.js 22.12 або новіший; додаткові npm-пакети не потрібні.

1. Скопіюйте `.env.example` у `services/feedback/.env`.
2. На сервері вручну задайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_BOT_CHAT_ID`.
   Використовуйте числовий ідентифікатор чату; для груп він може бути від'ємним.
   Користувач має почати діалог із ботом, або бот має бути доданий у потрібну групу
   з правом надсилати повідомлення.
3. Обмежте доступ до `.env` користувачем сервісу, наприклад `chmod 600 services/feedback/.env`.
4. Із кореня репозиторію запустіть:

```sh
node --env-file=services/feedback/.env services/feedback/server.cjs
```

За замовчуванням сервер слухає `127.0.0.1:8787`. Це локальний HTTP-сервіс;
сам запуск не створює публічного HTTPS endpoint і не вмикає відправлення в
розповсюдженій версії Limit. Публічну адресу необхідно окремо налаштувати в
desktop-конфігурації після розгортання relay.

Не додавайте секрети в `VITE_*`, renderer, репозиторій, інсталятор або публічні
логи. Не вставляйте токен у команди `curl`, URL у браузері чи тести: адреса Telegram
API містить його в шляху. `.env.example` навмисно містить порожні значення.

## HTTPS deployment

Запустіть один екземпляр relay під окремим користувачем за локальним HTTPS reverse
proxy. Сервіс не реалізує TLS самостійно. Proxy має приймати зовнішні з'єднання,
перевіряти обмеження розміру/частоти запитів і передавати лише `/feedback` на
`http://127.0.0.1:8787/feedback`. Закрийте порт 8787 від зовнішнього доступу.

За замовчуванням forwarding-заголовки ігноруються. Якщо reverse proxy працює на
цьому ж сервері, задайте `FEEDBACK_TRUST_PROXY=loopback` і **перезаписуйте**
`X-Real-IP` реальною адресою клієнта. Для nginx відповідна директива:

```nginx
proxy_set_header X-Real-IP $remote_addr;
```

Не копіюйте в цей заголовок довільний заголовок від клієнта. Relay довіряє лише
одній IP-адресі з `X-Real-IP`, лише від peer `127.0.0.1` або `::1`, і лише в
явно ввімкненому режимі `loopback`. `X-Forwarded-For` не використовується.
Для віддаленого proxy спершу потрібна окрема безпечна конфігурація; не вмикайте
довіру до довільних адрес.

Квоти в пам'яті: 5 спроб на IP за годину, 60 загалом за годину, до 2048 IP і до
4 запитів одночасно. При заповненні IP-таблиці нові IP відхиляються до звільнення
прострочених записів. Спроба з валідними HTTP-заголовками витрачає квоту навіть
за невалідного JSON або помилки Telegram. Перезапуск скидає квоти, тому proxy має
додатково обмежувати частоту; для кількох екземплярів потрібна спільна квота.
Публічний endpoint не є автентифікованим: перевірка Origin блокує запити браузера,
але не замінює захист від довільних HTTP-клієнтів.

`SIGINT` і `SIGTERM` припиняють приймання нових відгуків; поточні запити мають до
10 секунд на завершення. Після цього запити скасовуються й з'єднання закриваються.
Сервіс не веде черги та не повторює надсилання автоматично. Якщо timeout стався
після приймання повідомлення Telegram, повторне ручне надсилання може створити
дублікат. Успіх повертається лише після підтвердження Telegram.

## API

`POST /feedback`, `Content-Type: application/json` або
`application/json; charset=utf-8`; тіло до 24 KiB, без стиснення та без `Origin`.

```json
{
  "message": "Будь ласка, додайте календар тренувань.",
  "contact": "optional@example.com",
  "source": "health"
}
```

- `message`: 10–3000 UTF-16 одиниць після обрізання крайніх пробілів.
- `contact`: необов'язковий рядок до 200 UTF-16 одиниць після обрізання пробілів.
- `source`: тільки `health` або `settings`.
- Невідомі поля відхиляються; поля адресата чи токена в запиті неприпустимі.
- Керівні символи заборонені, крім табуляції та переведень рядка.

Успіх: HTTP 200, `{"ok":true}`. Помилки:

| HTTP                    | Тіло                                  |
| ----------------------- | ------------------------------------- |
| 400/403/404/405/413/415 | `{"ok":false,"error":"invalid"}`      |
| 429                     | `{"ok":false,"error":"rate_limited"}` |
| 503                     | `{"ok":false,"error":"unavailable"}`  |

Відповіді не містять токена, chat ID, тексту відгуку або помилок Telegram. Немає
CORS-дозволів. Telegram викликається через фіксований `sendMessage`, без
`parse_mode`, з вимкненими link previews і забороною redirects. Запит має загальний
timeout 10 секунд; відповідь Telegram обмежена 64 KiB.

Контракт Telegram: [офіційний sendMessage](https://core.telegram.org/bots/api#sendmessage).
Обмеження HTTP-сервера: [Node.js HTTP API](https://nodejs.org/api/http.html).

## Перевірка

```sh
node --test electron/tests/feedback-relay.test.cjs
```

Тести використовують підставний `fetch`, годинник і потоки в пам'яті: без
мережевих запитів, реальних токенів, читання `.env` чи надсилання повідомлень.
