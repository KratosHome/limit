# Побажання, Telegram і підтримка проєкту

Сторінка «Здоров’я та спорт» показує, що розділ ще в розробці. Форма побажань
також доступна в налаштуваннях. Вона надсилає тільки введене повідомлення,
необов’язковий контакт і назву розділу. Історія сайтів, задачі та дані здоров’я
не додаються до повідомлення.

## Де зберігаються ключі

```text
Limit → ваш HTTPS-сервіс /feedback → Telegram Bot API → ваш чат
```

`TELEGRAM_BOT_TOKEN` і `TELEGRAM_BOT_CHAT_ID` належать тільки серверу. Змінна
в `.env` не робить секрет безпечним, якщо її значення вбудувати в застосунок:
інсталятор можна розпакувати. Тому desktop-код цих змінних не читає, а каталог
`services/` і всі `.env` явно виключено з пакування та Git.

Використовується метод [sendMessage Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).
Бот має мати доступ до чату: для особистого чату спочатку відкрийте бота
в Telegram і натисніть Start.

## Локальний запуск

Потрібен Node.js 22.12 або новіший.

1. Скопіюйте `services/feedback/.env.example` у `services/feedback/.env`.
2. Заповніть токен і ID чату тільки в цьому файлі.
3. Запустіть `npm run dev:feedback`.

Ця команда запускає локальний сервіс на `127.0.0.1:8787` і dev-застосунок,
передаючи йому тільки локальну адресу сервісу. Зупинка команди завершує обидва
процеси. Якщо потрібен лише сервіс, використовуйте `npm run feedback:dev`.
Для вже запущеного вручну сервісу можна додати до `.env.local`:

```dotenv
LIMIT_FEEDBACK_DEV_URL=http://127.0.0.1:8787/feedback
```

Після цього звичайний `npm run dev` використовуватиме цей сервіс. Локальна
адреса не записується в реліз. Релізні копії не дозволяють локальний HTTP.

## Увімкнення в інсталяторах

1. Розгорніть [сервіс](../services/feedback/README.md) за публічною HTTPS-адресою.
2. Задайте його Telegram-змінні через секрети хостингу або захищений файл
   оточення **на сервері**.
3. Скопіюйте кореневий `.env.example` у `.env.public` і заповніть публічні URL:

```dotenv
LIMIT_FEEDBACK_URL=https://your-domain.example/feedback
LIMIT_DONATION_URL=https://your-donation-page.example/
```

4. Запустіть звичайну команду збірки / інсталятора.

`npm run build` створює `dist/support-config.json` тільки з цими двома URL.
Він потрапляє в інсталятор. У GitHub Actions задайте ці значення як Repository
variables `LIMIT_FEEDBACK_URL` і `LIMIT_DONATION_URL`; release workflow вже їх читає.
Токен не потрібно передавати в CI для desktop-збірки. Заміна токена на сервері
не потребує нової версії застосунку; зміна URL сервісу потребує нової збірки.

Порожній URL сервісу означає, що надсилання ще недоступне; форма чесно показує
цей стан і пропонує GitHub. Порожній URL донату показує інформацію про підтримку
без неіснуючої платіжної кнопки. Сховище проєкту:
[KratosHome/limit](https://github.com/KratosHome/limit).

Публічна форма має обмеження частоти, розміру повідомлень і паралельних запитів.
Вона не має вбудованого спільного «секретного ключа»: такий ключ також можна
витягти з інсталятора. Під час розгортання додайте обмеження частоти на HTTPS-проксі;
деталі та межі в документації сервісу.
